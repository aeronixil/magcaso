# Git and Flutter classroom

This curriculum contains 250 ordered learning cards: 25 detailed topics across Git and Flutter, with ten different practice stages for each topic. The stages move through diagnosis, prediction, guided work, debugging, comparison, evidence reading, verification design, adaptation, recovery, and teach-back. Each card includes a learning goal, an explanation, a worked example, a pitfall, key terms, a concrete context, and an exercise that asks for an observable answer.

## Generate lessons

From this directory, run:

```sh
python tools/build_curriculum.py --count 10
```

`--count` accepts any integer from 0 through 250. It writes the requested prefix in stable curriculum order to `assets/lessons/index.json` and writes one UTF-8 Markdown file per included card under `docs/lessons/`. Re-running the same count produces the same content. Increase the count to publish the next cards; a smaller count rewrites the index to that prefix and does not delete Markdown files generated by an earlier, larger run.

Each JSON entry has `id`, `title`, `topic`, `summary`, `body`, and `exercise` fields. IDs are stable and unique, so classroom progress and favorites can refer to a lesson without depending on its display title.

## Classroom activities

Learners should do the exercise before reading the worked example when the activity asks them to predict or diagnose. Encourage students to name the command or design choice, the evidence they expect, and the state they intend to preserve. For Git, use a disposable practice repository for commands that rewrite or discard data. For Flutter, use a small sample screen or a local branch and check behavior with narrow viewport sizes, long text, and failure states.

Exercises revisit each topic using different thinking skills instead of ten near-identical prompts. Instructors can ask pairs to compare answers, then have each learner explain the pitfall and a verification step. The JSON is suitable for a card interface; the individual Markdown files work as printable or linkable lesson notes.

## Search, favorites, and themes

The app currently searches lesson titles, topics, and summaries. It does not search lesson bodies or exercises. Favorites are held in memory for the current app session, so they clear when the app restarts. Theme selection also resets on restart. There is no lesson completion tracking. These are current app behaviors, not promises of persistence or progress synchronization.

The app supports its available themes; lesson text should remain readable in each, and controls should be labeled. Do not imply that favorite or theme choices are saved between launches, or show completion progress that the app does not track.

## Simulated commits and dates

The training history consists of 252 new, non-empty commits: one full app upgrade, 250 incremental lesson additions, and a 3D/AR studio feature inserted on 2025-09-28. Their subjects are marked `[classroom simulation]`. Both author and committer dates are set to reproducible simulated dates spanning 2024-09-28 through 2026-09-28. These dates are for a teaching visualization only; they do not establish when real work happened and must never be represented as authentic work dates.

The activity heatmap in `docs/activity.html` is rendered later by `tools/render_activity.py` from the actual new Git history. It visualizes those added commits and their simulated dates. The date range does not imply that the app used the Flutter or Dart SDK versions available at those historical dates: the upgraded app may use a modern SDK while its classroom commits are backdated for the simulation.

The original commits remain unchanged. The simulated training commits are new additions and do not rewrite, replace, or authenticate the repository's prior history. `tools/build_curriculum.py` generates lesson files and the index; it does not itself create commits or set Git timestamps.
